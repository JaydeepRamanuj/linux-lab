## The mental model

A **package** is one file, like `openssl_3.0.13-0ubuntu3.16_amd64.deb`, that holds three things: the files to install, a short description (name, version, what it **depends** on), and scripts that run as root to set it up. A **repository** is a web server holding thousands of packages and an index of them. Two programs share the work: **apt** decides what to install and downloads it, and **dpkg** unpacks it and keeps the record of what's on the machine.

The interesting part is trust. The download comes over the internet, often from a mirror nobody at Ubuntu runs, and it's going to run as root. apt trusts it because of one chain of checks that starts with a key already on your disk.

Two things follow. Packages from Ubuntu's repositories come with a checked chain from a key you already had to the bytes on your disk. A `.deb` or install script from a website comes with none of it, and its scripts still run as root. Where the installed files go is the [directory layout](/g/filesystem-layout); `dpkg -L` and `dpkg -S` show it for any package.

## Under the hood

**How a repository is laid out.** A repository has two parts. `dists/` holds the indexes: `dists/noble-updates/InRelease`, and under it `main/binary-amd64/Packages` for each component and architecture. `pool/` holds the `.deb` files themselves; each `Packages` entry names its file, like `pool/main/o/openssl/openssl_3.0.13-0ubuntu3.16_amd64.deb`. Your sources line picks a URL, suites and components, and apt builds the paths from those.

**Suites and components on Ubuntu.** `noble` is what shipped on release day and never changes. `noble-updates` holds bug fixes, `noble-security` holds security fixes, and `noble-backports` holds newer versions of some programs, at a lower priority so apt doesn't pick them unless you ask. The components say who looks after the software: `main` (Canonical supports it), `universe` (the community), `restricted` (drivers that aren't free software) and `multiverse` (other non-free software). Ubuntu's `universe` is about 65,000 packages; `main` is about 6,000.

**Versions and priorities.** apt installs the highest version from the highest-priority source. Versions compare piece by piece, with an optional **epoch** before a colon that beats everything after it: Ubuntu's `firefox` package is version `1:1snap1-0ubuntu5`, which counts as newer than any `140.0` without an epoch. Priorities come from `apt_preferences`: `500` for a normal repository, `100` for backports and for what's installed, and anything you set with a pin file in `/etc/apt/preferences.d/`. The NodeSource installer in the [curl pipe bash scenario](/s/curl-pipe-bash) writes pin files there so its `nodejs` beats Ubuntu's.

**Adding a repository the right way.** A third-party repository needs two things on your machine: its signing key and a sources entry. The key goes in `/etc/apt/keyrings/vendor.gpg`, and the entry says `Signed-By: /etc/apt/keyrings/vendor.gpg`, so that key is trusted for that repository only. Keys in `/etc/apt/trusted.gpg.d/`, where the old `apt-key add` put them, are trusted for **every** repository, including Ubuntu's. Without the key you get this, and apt ignores the repository:

```
W: GPG error: https://deb.nodesource.com/node_22.x nodistro InRelease: The following signatures couldn't be verified because the public key is not available: NO_PUBKEY 2F59B5F99B1BE0B4
E: The repository 'https://deb.nodesource.com/node_22.x nodistro InRelease' is not signed.
```

The fix is to install the key the vendor's instructions give, not to set `trusted=yes` or `AllowInsecureRepositories`, which turn the whole check off. A **PPA** (`ppa:user/name`) is the same thing hosted on Launchpad; `add-apt-repository` fetches its key and writes the entry for you. Whoever runs a repository you add can ship any package to your machine, including one that replaces a system package, so add only ones you'd trust with root.

**apt, apt-get and dpkg.** dpkg works on one `.deb` at a time and doesn't download anything or resolve dependencies. It only refuses: "dependency problems prevent configuration". apt does the planning and then calls dpkg. `apt` is the version for people (progress bars, colours, a friendlier `search`); `apt-get` and `apt-cache` keep stable output for scripts. When dpkg is left halfway, by an error or a closed terminal, the [fix a broken install scenario](/s/fix-broken-install) finishes the job.

**What dpkg remembers.** `/var/lib/dpkg/status` has an entry for each package with its state, which `dpkg -l` shows as two letters: `ii` installed, `iU` unpacked but not configured, `rc` removed but config files kept (see the [remove a package scenario](/s/remove-package)). `/var/lib/dpkg/info/` has the file lists and scripts for each package. `/var/lib/apt/extended_states` records which packages apt installed only as dependencies (`Auto-Installed: 1`); `autoremove` offers to remove those once nothing needs them. dpkg and apt each take a lock while they work, which is the [apt lock scenario](/s/apt-lock).

**Maintainer scripts and conffiles.** The scripts are shell scripts with root's full power, and dpkg runs them with arguments like `configure` or `upgrade`. Most are a few lines generated by Debian's tools to add a user, enable a systemd unit or rebuild a cache. Files listed in `conffiles` are handled specially: an upgrade never silently overwrites one you changed, and `apt remove` leaves them behind while `apt purge` deletes them.

**Updates without you.** On Ubuntu, `unattended-upgrades` installs security updates once a day through the `apt-daily-upgrade` timer ([scheduled tasks](/g/scheduled-tasks) shows how). That's often what holds the apt lock a few minutes after boot.

**Other distributions.** Fedora uses `.rpm` packages with `dnf` on top of `rpm`, and its repositories live in `/etc/yum.repos.d/`. Arch uses `pacman` with `.pkg.tar.zst` files. Both also sign each package file, not only the index, so a single downloaded package can be checked on its own. Debian and Ubuntu sign the index and check packages against it. The [which package scenario](/s/which-package) has the equivalent lookup commands.
