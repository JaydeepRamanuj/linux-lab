## The mental model

Three tables in the kernel decide where every packet goes.

- **Interfaces.** Each network device the kernel can send through: `lo` (loopback), `wlp2s0` (Wi-Fi), `enp0s31f6` (Ethernet), and virtual ones such as `docker0` or a VPN's `tun0`. An interface is up or down, and has a hardware (MAC) address if it's a real network card.
- **Addresses.** Each interface holds one or more IP addresses with a **prefix length**: `192.168.1.42/24` means "I'm `.42`, and every `192.168.1.x` address is on the same network as me". The prefix is what lets the kernel tell *near* from *far*.
- **Routes.** For every outgoing packet the kernel looks up the destination in the routing table. A destination on your own network goes straight out of the interface. Anything else goes to the **default route**: the gateway, which is your router.

Most network trouble on a single machine is one of these three tables being wrong or empty:

| Symptom | Table to check |
|---|---|
| Interface `DOWN`, or no `inet` line | Interfaces and addresses: no link, or DHCP failed (`169.254.x.x`) |
| No `default via …` line | Routes: you can reach the local network but nothing beyond it |
| Gateway `FAILED` in `ip neigh` | Neighbours: the router isn't answering on this network |
| All three fine, names fail | Not this layer: see [how a name becomes an IP](/g/dns-resolution) |

Some addresses mean something before you look anything up:

| Address | Meaning |
|---|---|
| `127.0.0.1`, `::1` | Loopback: this machine, never leaves it |
| `10.x`, `172.16–31.x`, `192.168.x` | Private ranges, used inside homes, offices and VMs |
| `169.254.x.x` | Self-assigned: DHCP didn't answer |
| `fe80::…` | IPv6 link-local: only valid on that one network |
| `0.0.0.0` | "Every address" for a listening socket, "anywhere" in a route |

## Under the hood

**Who sets all this.** Nothing in `ip`'s output is stored in a file. A network manager configures the kernel at boot and whenever a network appears. On Ubuntu Desktop that's **NetworkManager**: it joins Wi-Fi, asks the router for an address with DHCP, and adds the default route and DNS servers it hands out. On Ubuntu Server, **netplan** reads YAML from `/etc/netplan/` and passes it to systemd-networkd (`renderer: networkd`); on Desktop netplan hands everything to NetworkManager. `sudo ip addr add` and `sudo ip route add` work, but only until the manager next applies its own settings. ShellGyan rates those as `elevated`, including short forms such as `ip r a` and `ip link s`: iproute2 accepts any prefix of a verb.

**Interface names.** The kernel names network cards `eth0`, `wlan0` in the order it finds them, which can change between boots. systemd renames them from where the hardware sits: `en` for Ethernet, `wl` for wireless, then `o1` for an onboard device, or `p2s0` for PCI bus 2, slot 0. So `wlp2s0` is "the Wi-Fi card on PCI bus 2". The name stays the same as long as the card stays in the same slot. Virtual machines, containers and WSL often keep `eth0`. [Kernel modules and drivers](/g/kernel-modules) covers how the card's driver loads in the first place.

**Most specific route wins.** With routes for `0.0.0.0/0` (default), `10.0.0.0/8` and `10.8.0.0/24`, a packet to `10.8.0.5` takes the `/24`, the longest matching prefix. That's how a VPN works: it adds routes for the company network through `tun0`, or replaces the default route entirely. When two routes match equally, the lower `metric` wins, which is how NetworkManager prefers a cable over Wi-Fi when both are connected. `ip route get ADDRESS` answers "which way would this go?" without guessing.

**The kernel answers for its own addresses.** A second table, `ip route show table local`, lists the addresses that belong to this machine. Traffic to any of them, even to your own Wi-Fi address, never touches the network card: it goes through `lo`. That's why a server bound to `0.0.0.0` answers `curl http://192.168.1.42:3000` from the same machine. [Ports and sockets](/g/ports-sockets) covers the listening side.

**NAT, twice.** Your router translates between private addresses inside and one public address outside, and keeps a table of which inside machine started which connection, so replies find their way back. WSL adds a layer: Linux gets a private `172.x` address behind Windows, and Windows translates again on the way out. A server inside WSL reaches the Windows browser through `localhost` forwarding, but not other devices on your network unless you set that up.

**IPv6.** Every interface gets an `fe80::` link-local address as soon as it's up, and that's all it has in WSL's NAT setup. On a home network with IPv6, the router also announces a prefix, and the machine builds global addresses from it (SLAAC), with no DHCP needed. Ubuntu adds temporary addresses for outgoing connections so websites can't track one fixed address. Without a global address or an IPv6 default route, tools that try IPv6 first report `network unreachable` and fall back to IPv4.

**`ifconfig` and `route`.** They come from `net-tools`, which isn't installed on new Ubuntu systems and doesn't know about everything the kernel can do (several addresses per interface, policy routing). `ip a` and `ip r` replace them; [which package has the command](/s/which-package) finds `net-tools` if a tutorial insists.

**Where the kernel keeps it.** `/sys/class/net/` has a folder per interface, with files such as `address`, `mtu` and `operstate`. `/proc/net/route` is the old text form of the routing table, with addresses in hex. Kernel settings such as `net.ipv4.ip_forward` live under `/proc/sys/net/` ([/proc and /sys](/g/proc-sys)).
