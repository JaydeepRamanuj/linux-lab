## The mental model

A **socket** is the kernel's handle for one end of network traffic. A program asks the kernel for one and gets back a **file descriptor**, the same kind of small number it gets for an open file. Reading and writing it sends and receives data.

A **port** is a number from 1 to 65535 that the kernel uses to decide which socket incoming traffic belongs to. A server claims a port in three steps: **bind** (put this socket on address `0.0.0.0`, port `3000`), **listen** (accept connections on it) and **accept** (hand me the next connection). Each accepted connection is a new socket. The listening one stays where it is, waiting for the next.

**"Address already in use"** (`EADDRINUSE`) is what `bind` answers when another socket already holds that address and port. Nothing is wrong with the port. The kernel refuses because the first owner is still there. Find that process and stop it, and the port is free. The [port in use scenario](/s/port-in-use) walks through it.

Three facts explain most of the rest:

- **A connection is four values.** Local address, local port, remote address, remote port. Every client of your server shares port 3000 on your side. The client's side gets its own random port, from the range in `ip_local_port_range`.
- **The address matters.** `127.0.0.1` (loopback) is reachable only from this machine. `0.0.0.0` (`*` or `[::]` in some tools) means every address the machine has.
- **Ports below 1024 need privileges.** Binding to 80 or 443 as a normal user fails with Permission denied. That's why dev servers use 3000, 5173 or 8080.

## Under the hood

**Sockets really are file descriptors.** `ls -l /proc/<PID>/fd` lists them next to the process's open files, as `socket:[823]`. The number is an inode in the kernel's socket filesystem. That's how `lsof`, "list open files", can answer questions about ports: it walks every process's fd list and matches the socket inodes against the kernel's socket table. `ss` asks the kernel's socket table directly.

**Children inherit sockets.** When a process starts another, the child gets a copy of its file descriptors, sockets included, unless they're marked close-on-exec. If the parent dies, the child still holds the socket and the port stays taken. `ss -ltnp` then shows the child's name, not the server you started. That's the usual reason why killing the server didn't free the port.

**TIME_WAIT.** When a TCP connection closes, the side that closed first keeps a small record of it for 60 seconds on Linux. That way, a late packet from the old connection can't be mistaken for part of a new one. While that record exists, a plain `bind` to the same port can still fail with `EADDRINUSE`, even though nothing is listening. Servers avoid this by setting the `SO_REUSEADDR` option before binding, and most do. If a server you wrote yourself won't restart for a minute after stopping, that's the cause. `ss -tan` shows those records in state `TIME-WAIT`.

**Sharing a port on purpose.** `SO_REUSEPORT` lets several sockets bind the same address and port, and the kernel spreads new connections across them. It's opt-in: every socket has to ask for it, so it never explains an accidental conflict.

**Port 1024 is a setting.** "Privileged" means below `/proc/sys/net/ipv4/ip_unprivileged_port_start`, 1024 by default. A program can also get the `CAP_NET_BIND_SERVICE` capability instead of running as root.

**Not every socket has a port.** Unix domain sockets use the same calls but bind to a path, like `/run/docker.sock` or `/run/systemd/journal/socket`, and never leave the machine. `ss -x` lists them. They're one reason Linux can say "everything is a file".

**UDP.** UDP has no connections and no listen step, but a bound UDP port is still owned by one socket, so it can conflict the same way. `ss -lun` lists UDP sockets.
