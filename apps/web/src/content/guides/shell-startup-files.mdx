## The mental model

A shell starts with nothing but the environment it inherited. Everything else, your aliases, your prompt, extra `PATH` folders, comes from files it runs on the way up. Which files depends on two yes-or-no questions:

- **Login shell?** The first shell of a session: SSH, a text console, `su -` or `sudo -i`, or `bash -l`. It's meant to set up the session once.
- **Interactive?** It reads commands from you and shows a prompt. A script, or `bash -c '…'`, is not.

| Shell | Example | Bash reads |
|---|---|---|
| Login, interactive | SSH into a server | `/etc/profile`, then the **first** of `~/.bash_profile`, `~/.bash_login`, `~/.profile` |
| Not login, interactive | A new terminal window or tab on the desktop | `/etc/bash.bashrc`, then `~/.bashrc` |
| Not interactive | `./script.sh`, `bash -c '…'`, cron jobs | Nothing, except a file named in `$BASH_ENV` |

The two sets of files look unrelated, but Ubuntu links them so you rarely need to think about it. Here's an SSH login:

A terminal window skips the first three stages and starts at `~/.bashrc`. So the practical rule on Ubuntu is:

- **Aliases, functions, the prompt, shell options:** `~/.bashrc` (or `~/.bash_aliases`). They apply to every interactive bash, login or not. The [persistent alias scenario](/s/persistent-alias) does this.
- **Environment variables and `PATH`:** `~/.bashrc` works for terminals. Use `~/.profile` if programs launched from the desktop need them too, then log out and back in. The [Add a folder to PATH scenario](/s/add-to-path) uses `~/.bashrc`.

## Under the hood

**Why the desktop reads `~/.profile`.** On Ubuntu, the graphical login runs your session through a login shell, so `~/.profile` runs once at the start, and apps started from the dock or app menu inherit that environment. They never see `~/.bashrc`, which only runs in terminals. Changes to `~/.profile` take effect at the next login. A terminal window on the desktop isn't a login shell because the session already did that work. GNOME Terminal has an option to change this, which is rarely what you want.

**The `~/.bash_profile` trap.** Many guides written for other systems say "add this to `~/.bash_profile`". On Ubuntu that file doesn't exist, and creating it changes which file a login shell reads: `~/.profile` stops running, along with its `PATH` lines and its call to `~/.bashrc`. If you need one, make it a single line that hands over: `[ -f ~/.profile ] && . ~/.profile`. Fedora is the other way round: it ships a `~/.bash_profile` that runs `~/.bashrc`, and no `~/.profile`.

**Why `/etc/bash.bashrc` exists.** Upstream bash reads only `~/.bashrc` for interactive non-login shells. Debian and Ubuntu build it to read the system-wide `/etc/bash.bashrc` first, so administrators can set defaults for every user. Fedora uses `/etc/bashrc` instead, called from the user's `~/.bashrc`.

**How bash knows.** A login shell is one started with `-l` or `--login`, or whose name (`$0`) starts with a dash. `login` and `sshd` start it as `-bash`, which is how it recognises itself. Interactive means started with `-i`, or with no script or `-c` and with stdin and stderr connected to a terminal. `$-` contains `i` in that case, which is exactly what the guard at the top of `~/.bashrc` checks.

**`source` versus a new shell.** `source ~/.bashrc` (or `. ~/.bashrc`) runs the file inside the current shell, so the changes apply there. It also runs everything again: a line like `PATH="$HOME/go/bin:$PATH"` adds a second copy each time. That's harmless, but it's why `PATH` can grow long. `exec bash` replaces the shell with a fresh one instead, which starts clean but keeps exported variables. Opening a new terminal is the cleanest test of what your files really do.

**Seeing what runs.** `bash -lx -c exit 2>&1 | less` starts a login shell with tracing on and shows every line of every startup file as it runs, in order. It's the fastest way to find which file sets a variable you don't recognise.

**sh is not bash.** On Ubuntu, `/bin/sh` is `dash`, a smaller shell. As a login shell it reads `/etc/profile` and `~/.profile`, never `~/.bashrc`. That's why `~/.profile` checks `$BASH_VERSION` before running `~/.bashrc`: the file may be read by a shell that would choke on bash syntax.
