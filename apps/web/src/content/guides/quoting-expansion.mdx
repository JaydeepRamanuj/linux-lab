misconceptions:
  - myth: "Quotes are part of the value."
    reality: "Quotes are instructions to the shell, and the last expansion step removes them. `name=\"Jo\"` stores `Jo`, two characters."
  - myth: "`$var` and `\"$var\"` are the same unless the value has spaces."
    reality: "Unquoted, the value is also checked for glob characters. `x='*'; echo $x` lists the folder. A value that's empty disappears entirely unquoted, so `[ $x = y ]` turns into `[ = y ]` and fails with a syntax error."
  - myth: "Single quotes and double quotes are interchangeable."

## The mental model

After bash has split your line into words, it rewrites each word in a fixed order. Every step can change what the next step sees. Here is one line going through all of them, with `pattern='*.md'` and `name='my notes.txt'`:

Quotes decide which steps run on each part of a word:

| | Expansion (`$`, `$(…)`) | Splitting | Globs |
|---|---|---|---|
| No quotes | yes | yes | yes |
| `"double"` | yes | no | no |
| `'single'` | no | no | no |

So the one rule worth keeping: **put double quotes around every `$`** unless you want splitting and globbing on the result. The [expansion and quoting scenario](/s/expansion-quoting) shows the bugs this prevents, file names with spaces above all.

## Under the hood

**The third step is several at once, left to right.** Parameter expansion, command substitution, arithmetic and process substitution (`<(…)`) are one step in bash's order, done in the order they appear on the line. A `$(…)` runs in a subshell, a child process, and its output replaces it with every trailing newline removed. That's why `"$(printf 'a\n\n\n')"` is just `a`.

**Splitting uses `IFS`.** Word splitting cuts at the characters in the `IFS` variable, by default space, tab and newline. `IFS=: ; p='x:y'; printf '[%s]\n' $p` prints `[x]` and `[y]`. Scripts that set `IFS` and forget to restore it break every unquoted expansion after it. Spaces and tabs in a row count as one separator, while other `IFS` characters count once each, so `a::b` split on `:` gives three fields, one empty.

**What a glob can and can't match.** `*` and `?` don't match a leading `.`, so `*` skips hidden files, and they never match a `/`. A pattern with no match is left as it is. Two options change that: `shopt -s nullglob` removes it instead, and `shopt -s failglob` makes it an error. Zsh errors by default, with `no matches found`, which is why an unquoted `?` in a URL fails in zsh but works in bash: `curl https://x.test/a?b=1` should be quoted in both.

**Globs in variables expand late.** `x='*'` stores one character. The glob only happens when `$x` is used unquoted, at step 5. A filename stored in a variable can contain `*` and turn into a list of other files.

**`"$@"` is the special case.** Inside double quotes, `$@` expands to one word per positional parameter, keeping each exactly as it was passed, spaces and all. Arrays work the same way: `"${arr[@]}"` gives one word per element. It's the only way to pass a script's arguments on to another command unchanged. `$*` and `$@` without quotes are split and globbed like anything else.

**Other quoting forms.** A backslash quotes the next character. `$'…'` (ANSI-C quoting) understands escapes like `\t`, `\n` and `\'`, so `$'it\'s'` works where `'it\'s'` doesn't. `$"…"` is for translations and behaves like double quotes otherwise. Inside double quotes, `\` keeps its meaning only before `$`, `` ` ``, `"`, `\` and a newline.

**Where splitting doesn't happen.** In an assignment, `b=$a` gets the whole value, spaces included, and no globbing. Inside `[[ … ]]`, variables aren't split or globbed either. (On the right of `==`, an unquoted value is a *pattern*, though: `[[ $f == *.md ]]` matches by suffix.) `case` words and here-strings follow the same rule. Bash's old `[ … ]` is a normal command, so everything is split there.

**Aliases come even earlier.** They're replaced while the line is split into words, before any of this. That's why an alias can contain operators like `|` and `&&`, and why aliases aren't expanded in scripts unless `shopt -s expand_aliases` is set.
