  - myth: "The kernel finds and mounts my disk by itself."
    reality: "On Ubuntu the kernel starts a small temporary system first, the initramfs, which loads the storage drivers, unlocks an encrypted disk if needed, and mounts the real root. That's why a disk problem can drop you at an `(initramfs)` prompt."
  - myth: "`systemd-analyze blame` lists what to disable to boot faster."
    reality: "It lists how long each unit took to start, and units start in parallel. A slow unit may only have been waiting for another one, and many don't delay the login screen at all. `critical-chain` shows what the boot actually waited for."
  - myth: "A new kernel is used as soon as apt installs it."
    reality: "The running kernel can't be swapped out. apt installs the new `vmlinuz` and `initrd.img`, updates GRUB's menu, and the new kernel runs from the next boot. Until then `uname -r` still shows the old one."
  - myth: "Secure Boot checks everything that boots."
    reality: "It checks the chain of programs: the firmware checks shim, shim checks GRUB and the kernel, the kernel checks modules. The initramfs isn't signed or checked on Ubuntu."

## The mental model

Booting is a relay. Each stage is a program whose only job is to find and start the next one, and each runs with more of the system available than the one before:

When a boot fails, the screen you're left at tells you which stage stopped:

| You see | It stopped in |
|---|---|
| Maker's logo, no GRUB, "no bootable device" | Firmware: wrong boot order, or the EFI partition is damaged |
| `grub>` or `grub rescue>` | GRUB: it can't find its files or the kernel |
| `Kernel panic - not syncing` | Kernel: often a missing or broken initramfs |
| `(initramfs)` prompt | initramfs: the root disk wasn't found, or needs a check |
| "You are in emergency mode" | systemd: usually a bad line in `/etc/fstab` |
| Black screen after the logo | Login stage: often the graphics driver |

## Under the hood

**UEFI and the EFI partition.** Modern PCs use UEFI firmware; older ones used BIOS, which loaded the first sector of the disk. Your system booted with UEFI if `/sys/firmware/efi` exists. The firmware keeps a list of boot entries (`efibootmgr` lists them) and loads `EFI/ubuntu/shimx64.efi` from the EFI system partition. Ubuntu's `grub.cfg` there is a three-line stub that points GRUB at the real menu, `/boot/grub/grub.cfg`.

**Secure Boot.** The firmware runs only programs signed by a key it trusts, which on most PCs means Microsoft's. Ubuntu's shim is signed by Microsoft and carries Canonical's key; it uses that to check GRUB and the kernel, both signed by Canonical. The kernel then refuses unsigned [kernel modules](/g/kernel-modules). The initramfs isn't checked.

**GRUB's menu.** Ubuntu hides the menu when it's the only system installed. Hold Shift (BIOS) or tap Esc (UEFI) during boot to see it. **Advanced options for Ubuntu** lists the older kernel and a recovery mode, which boots to a root shell menu without the desktop. `e` on an entry edits its command line for one boot. Permanent changes go in `/etc/default/grub` (such as `GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"`), followed by `sudo update-grub`, which rewrites `/boot/grub/grub.cfg`; don't edit that file directly.

**The kernel command line.** Parameters the kernel doesn't use are passed on to the initramfs and systemd. Ones worth knowing:

| Parameter | Effect |
|---|---|
| `quiet splash` | Hide messages, show the logo. Remove both to see what boot is doing |
| `root=UUID=…` `ro` | The root filesystem, mounted read-only until it's checked |
| `systemd.unit=rescue.target` | Boot to a root shell with only local disks mounted |
| `systemd.unit=emergency.target` | Even less: a root shell with almost nothing started |
| `break=premount` | Stop inside the initramfs with a shell |
| `nomodeset` | Basic graphics only, for when the graphics driver hangs |

**Inside the initramfs.** Ubuntu builds it with initramfs-tools: a small busybox system with `/init` (a shell script), udev and the kernel modules for your storage. Its scripts run in phases (`init-top`, `premount`, `local-top` and so on), find the root device, check it and mount it, then hand over to the real `/sbin/init`. `lsinitramfs /boot/initrd.img | less` lists what's inside. `sudo update-initramfs -u` rebuilds it, which apt does for you after kernel updates and after installing anything that adds a hook, such as disk encryption. Fedora builds its initramfs with dracut and runs systemd inside it, so its `systemd-analyze` adds an `(initrd)` time; Arch uses mkinitcpio.

**systemd's part.** From here [systemd units and targets](/g/systemd-units) take over. `bootup(7)` draws the order: mounts and swap, then `sysinit.target`, then sockets, timers and paths, `basic.target`, and the services wanted by `multi-user.target` and `graphical.target`. Units without an order between them start at the same time, which is why boot logs look interleaved. `systemctl get-default` names the final target.

**Reading boot problems after the fact.** The journal keeps earlier boots: `journalctl -b -1 -p warning` shows the warnings and errors from the previous boot, and `journalctl --list-boots` lists them ([where logs live](/g/journald-logs)). `systemctl --failed` lists units that didn't start. `systemd-analyze blame` sorts units by start time, but they start in parallel, so check `critical-chain` before you disable anything.

**Under WSL** there's no firmware, GRUB or Ubuntu kernel. Windows starts a virtual machine with Microsoft's kernel and its own initramfs, whose `/init` is WSL's. With systemd enabled in `/etc/wsl.conf`, WSL's `/init` starts systemd as PID 1 of the distribution and stays alongside it as PID 2; from there the systemd part of the boot is the same as on a laptop. `/boot` is empty.
