## The mental model

Most files are stored data. The files in `/proc` and `/sys` are **questions and answers**: opening `/proc/meminfo` and reading it runs a small piece of kernel code that writes out the current memory counters. Read it again a second later and you get new numbers. Writing to a file under `/proc/sys` or `/sys` changes a setting inside the running kernel.

Many everyday tools are readers of these two folders:

| Tool | Reads |
|---|---|
| `ps`, `top`, `pgrep` | `/proc/<PID>/stat`, `status`, `cmdline` for every process |
| `free` | `/proc/meminfo` |
| `uptime` | `/proc/uptime` and `/proc/loadavg` |
| `lsof` | `/proc/<PID>/fd` for every process |
| `mount`, `findmnt` | `/proc/self/mounts` |
| `lsblk` | `/sys/block` and `/sys/class/block` |
| `sysctl` | `/proc/sys/…` |

So when a tool's output puzzles you, the raw file is usually one `cat` away.

### What's where

| Path | What it tells you |
|---|---|
| `/proc/<PID>/` | One folder per process: `status`, `cmdline`, `environ`, `cwd`, `exe`, `fd/`, `limits` |
| `/proc/self/` | The process that's reading |
| `/proc/meminfo`, `/proc/cpuinfo`, `/proc/loadavg` | Memory, CPUs, load |
| `/proc/sys/` | Kernel tunables, the ones `sysctl` shows |
| `/sys/class/net/<if>/` | Network interfaces: address, MTU, state, byte counters |
| `/sys/block/<disk>/` | Disks: size, whether it spins (`queue/rotational`) |
| `/sys/class/power_supply/BAT0/` | Laptop battery: `capacity`, `status` |
| `/sys/class/backlight/` | Screen brightness |
| `/sys/module/` | Loaded kernel modules and their parameters |

## Under the hood

**A folder per process.** Every running process has `/proc/<PID>/`, which disappears when it exits. [Processes, PIDs and the tree](/g/processes-basics) uses `status` and the tree; [file descriptors](/g/file-descriptors) uses `fd/` and `fdinfo/`; [inherited environments](/g/environment-variables) uses `environ`. `cwd`, `exe` and `root` are symlinks to the working folder, the program file and the root folder. Permissions protect the private parts: `environ` and `fd/` of another user's process are closed to you, while `status` and `cmdline` are open, which is why `ps aux` can list everyone's commands.

**`sysctl` is `/proc/sys` with dots.** `sysctl vm.swappiness` reads `/proc/sys/vm/swappiness`. The files belong to root and are mode `644`, so anyone reads and only root writes: as a normal user, `echo 1 > /proc/sys/vm/swappiness` fails with Permission denied. `sudo sysctl -w vm.swappiness=10` changes it until the next reboot.

**Making settings stick.** At boot, `systemd-sysctl.service` applies every `*.conf` file from `/usr/lib/sysctl.d/` (the distribution's defaults) and `/etc/sysctl.d/` (yours, which win for the same file name). Ubuntu's own files set things like `kernel.pid_max` and the protected links of [inodes and links](/g/inodes-links). Add a file such as `/etc/sysctl.d/90-local.conf` with `vm.swappiness = 10`, and `sudo sysctl --system` applies it now.

**A tunable you may meet: file watchers.** Dev servers and editors watch files with inotify, and each watched file costs one watch from `fs.inotify.max_user_watches`. Run out and you get `ENOSPC: System limit for number of file watchers reached`, which has nothing to do with disk space. The kernel picks the default from the amount of RAM; it was 524288 on the test machine. Raise it with a `sysctl.d` file as above.

**`/sys` is the device model.** It lays out every device the kernel knows as a tree under `/sys/devices`, the way they're connected: bus, controller, device. `/sys/class` and `/sys/block` are shortcuts into that tree, made of symlinks: `/sys/class/net/eth0` points somewhere deep in `/sys/devices`. The rule is one value per file, as plain text, which makes `/sys` easy to read from scripts. When a device appears, the kernel announces it, and udev reacts by creating the `/dev` nodes and `/dev/disk/by-uuid` links described in [mounts and block devices](/g/mounts-devices).

**Sizes, `tail -f` and seeking.** Because content is generated on read, `ls -l` reports 0 for most files, and some files change between two reads. Programs should read them in one go. `tail -f` never sees them grow; use `watch cat /proc/loadavg` to see a value change.

**Writing to `/sys`.** Some files there are writable by root, and writing changes hardware or driver state right away: `echo 50 | sudo tee /sys/class/backlight/*/brightness` sets the screen brightness. Like `/proc/sys`, these changes don't survive a reboot. Note the `tee`: `sudo echo 50 > …` fails, because the redirect is done by your own shell, as [how sudo works](/g/how-sudo-works) explains.

**Under WSL** you'll find no battery or backlight, and the disks and network card are virtual (`eth0`, `sda`…`sdd`), but `/proc` and `/sys` work the same.
