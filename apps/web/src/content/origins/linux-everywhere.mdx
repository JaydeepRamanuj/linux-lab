## The short version

For years people predicted "the year of the Linux desktop", and on desktops and laptops Linux has stayed a small minority. Meanwhile it took over nearly everything else. The internet's servers mostly run it, and so do most cloud virtual machines. Every computer on the TOP500 list of the world's fastest supercomputers runs Linux, and has since November 2017. Android, the most common operating system on phones, is built on the Linux kernel, as are ChromeOS, most home routers, smart TVs, car dashboards and countless embedded devices.

Several things made that happen. Linux was free to use and to change, so companies could fit it to their hardware without asking permission or paying per copy. It ran on many processor architectures. And because it was a Unix-like system, people who knew Unix could use it immediately, while it ran on cheap PC hardware instead of expensive Unix workstations.

The last big shift was containers. Two kernel features, namespaces and control groups, let a process run with its own view of the system and limits on what it can use. Docker, in 2013, made those features easy to use, and Kubernetes made it possible to run thousands of containers across many machines. Today a large share of software is packaged and run that way, on Linux.

## Servers and the cloud

Linux arrived on servers in the late 1990s, replacing commercial Unix on machines that cost a fraction as much. Web servers were the first big use: Linux with Apache, MySQL and PHP or Perl (the "LAMP" stack) ran a large part of the early web. Red Hat and SUSE sold the support contracts and certifications businesses needed, and IBM, HP, Dell and Oracle certified their hardware and software on it.

The cloud built on that. A cloud provider needs an operating system it can run on hundreds of thousands of machines, change freely, and offer to customers without paying per copy. Linux fits all three, so the hosts behind the big clouds largely run it, and Linux images are the default choice for virtual machines and the base for nearly all containers. Even Microsoft, whose Azure cloud also sells Windows, ships its own Linux distribution for its infrastructure.

## Supercomputers

The TOP500 list ranks the world's fastest computers twice a year. In the 1990s, it was dominated by commercial Unix and custom systems. Linux clusters, built from many ordinary servers, moved up the list through the 2000s. From the November 2017 list onwards, **all 500** systems have run Linux, and the latest list, from June 2026, is no different.

The reasons are practical: the kernel's source can be tuned for each machine's network and scheduler, there's no per-node licence to pay for thousands of nodes, and the scientific software is developed on Linux in the first place.

## Phones, laptops and things

**Android**, first released on a phone in 2008, uses the Linux kernel with Google's own user space on top. It has no GNU tools and no X or Wayland: it has its own C library (Bionic), its own init and its own Java-based application framework. Google maintains Android Common Kernels based on Linux's long-term releases, so the same kernel changes eventually reach both your phone and your server. Android is the clearest example of Linux being a kernel and not a whole operating system: by number of devices, it's the most common way people use Linux, mostly without knowing it.

**ChromeOS**, on Chromebooks since 2011, is a Linux system built with Gentoo's tools, shipped as a sealed image that updates itself. It can also run a Debian container for Linux apps.

**Embedded Linux** is everywhere a device needs networking, a screen or a file system, but not a full PC: routers, network storage, smart TVs, set-top boxes, cameras, car infotainment systems, industrial controllers, and the base stations of mobile networks. Projects such as Yocto and Buildroot build small, custom Linux systems for such hardware, and BusyBox replaces the GNU tools with one small program.

**Desktops and laptops** are the exception. Linux has a small share there, though larger among developers, and the Steam Deck brought a Linux-based system to a large number of gamers through SteamOS.

## Linux inside Windows: WSL

Microsoft's **Windows Subsystem for Linux** first appeared in 2016. WSL 1 translated Linux system calls into Windows ones, which ran most command-line programs but not all. WSL 2 changed approach: it runs a real Linux kernel inside a lightweight virtual machine and runs each distribution as an isolated container inside it, which gives full system call compatibility and, now, systemd. Microsoft made WSL itself open source. Many developers' first Linux system today is Ubuntu under WSL.

Both features came in stages. The idea goes back to `chroot`, in Seventh Edition Unix, and to FreeBSD's jails. Linux added namespaces one kind at a time: mount namespaces first, then UTS, IPC, PID and network namespaces, with user namespaces complete in Linux 3.8 in 2013, which made unprivileged containers possible. Control groups, from engineers at Google, were merged in Linux 2.6.24 in January 2008; a redesigned version, cgroups v2, became official in 4.5.

**LXC** (2008) was the first widely used tool to combine them. **Docker**, released in 2013, made it easy: a simple image format, layered filesystems, a registry to share images, and one command to build and run them. Its image and runtime formats became open standards under the Open Container Initiative, so tools like Podman run the same images. **Kubernetes**, which Google released in 2014 based on its internal systems, schedules containers across many machines; it reached 1.0 in July 2015 and was given to the new Cloud Native Computing Foundation.

Because every container shares the host's kernel, a Linux container needs a Linux kernel. On macOS and Windows, Docker Desktop runs a small Linux virtual machine to provide one.

## Why it matters today

- **Containers are processes.** On the host, `ps aux` shows a container's programs like any others. Inside, they see their own PID 1. The [processes guide](/g/processes-basics) and [`/proc`](/g/proc-sys) explain both views: `ls -l /proc/self/ns` shows the namespaces your shell is in.
- **Limits come from cgroups.** A container killed for using too much memory was killed by the kernel's OOM killer inside its cgroup, the same mechanism systemd uses for services.
- **The kernel is shared.** A container can't run a different kernel or load its own modules. What's inside is a userland: a distribution without a kernel. See [kernel and user space](/g/kernel-user-space).
- **Your phone, router and laptop run the same kernel family.** What you learn about processes, files and permissions on a server applies, with different userlands on top.
